# Zaidan Agent

Zaidan Agent ports shadcn-style React components to SolidJS. The setup is
deliberately small: one shared skill describes the workflow and target paths;
one translation skill describes React-to-SolidJS patterns.

## Flow

1. Determine whether the component comes from shadcn or an external
   shadcn-style registry.
2. Fetch the React source to transform.
3. Open a playground or docs URL for the original component when available, so
   behavior can be observed before porting.
4. When running inside the Zaidan repo, fetch docs and examples too.
5. Transform the component, and optionally docs/examples, using the
   `react-to-solid` skill.
6. Run the local Zaidan app and test the result in a browser.
7. When running inside the Zaidan repo, update
   `src/registry/kobalte/registry.json`.

## Files

| File | Role |
| --- | --- |
| `.agents/skills/zaidan-agent/SKILL.md` | Shared workflow, inputs, source URLs, target paths, browser testing, validation, registry updates, and report shape |
| `.agents/skills/react-to-solid/SKILL.md` | React-to-SolidJS transformation patterns |
| `.agents/skills/react-to-solid/docs/*` | Optional deeper references for Kobalte, Corvu, Base UI, and dependency mappings |
| `AGENTS.md` | Thin pointer to the shared skills |

There are no project-local agent personas. If work needs to be split, the
running agent can launch ordinary subagents with task-specific prompts.

## Usage

Clone the repository and install dependencies:

```bash
git clone https://github.com/carere/zaidan.git
cd zaidan
bun install
```

Ask your coding agent directly:

```txt
Port the shadcn dialog component to Zaidan.
```

Or provide explicit external sources:

```txt
Port this React component to Zaidan:
source: https://example.com/components/fancy-card.tsx
playground: https://example.com/docs/fancy-card
docs: https://example.com/docs/fancy-card.mdx
examples: https://example.com/examples/fancy-card.tsx
```

## Outputs

| Output kind | Target |
| --- | --- |
| UI component | `src/registry/kobalte/ui/<name>.tsx` |
| UI example | `src/registry/kobalte/examples/ui/<name>-example.tsx` |
| Block files | `src/registry/kobalte/blocks/<name>/` |
| Block example | `src/registry/kobalte/examples/blocks/<name>-example.tsx` |
| UI docs | `src/pages/ui/kobalte/<name>.mdx` |
| Block docs | `src/pages/blocks/kobalte/<name>.mdx` |
| Registry manifest | `src/registry/kobalte/registry.json` |

## Validation

Use focused checks while iterating:

```bash
bun biome check --write <changed-files>
bun run compile
bun run r:validate:kobalte
bun run r:build:kobalte
```

Use the browser available in your agent harness to test the transformed
component. Run the registry build when publishable registry files or
`src/registry/kobalte/registry.json` changed.
