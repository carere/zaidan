`MessageScroller` is a Solid chat transcript scroller for saved conversations and live responses. It keeps the reader in control: streaming output follows only at the live edge, appending a turn can preserve nearby context, and prepended history does not displace the visible row.

## What Makes a Great Streaming Chat Experience

Streaming changes a simple message list into a scroll-state problem. New content should arrive without taking readers away from a selection, an older reply, a keyboard interaction, or a link they are following.

1. Move only when the reader has chosen to follow.
2. Keep following while the reader stays at the live edge.
3. Treat scrolling, keyboard navigation, and direct jumps as reader intent.
4. Start a new turn near the top of the viewport, with a little previous context still visible.
5. Let off-screen content arrive quietly, and make it easy to jump back to it.
6. Reopen a saved transcript at a meaningful turn rather than always at its final pixel.
7. Keep the visible row stable while history, images, or rich content change layout.
8. Keep the transcript navigable without noisy announcements.

**Never move the reader against their intent.**

## Usage

```tsx showLineNumbers
import { For } from "solid-js";
import {
  MessageScroller,
  MessageScrollerButton,
  MessageScrollerContent,
  MessageScrollerItem,
  MessageScrollerProvider,
  MessageScrollerViewport,
} from "~/components/ui/message-scroller";
```

```tsx showLineNumbers
<MessageScrollerProvider autoScroll>
  <MessageScroller>
    <MessageScrollerViewport>
      <MessageScrollerContent>
        <For each={messages}>
          {(message) => (
            <MessageScrollerItem
              messageId={message.id}
              scrollAnchor={message.role === "user"}
            >
              <Bubble>Message content</Bubble>
            </MessageScrollerItem>
          )}
        </For>
      </MessageScrollerContent>
    </MessageScrollerViewport>
    <MessageScrollerButton />
  </MessageScroller>
</MessageScrollerProvider>
```

`MessageScroller` fills its parent, so place it in a height-constrained layout.

```tsx
<div class="flex h-screen flex-col">
  <MessageScrollerProvider>
    <MessageScroller class="flex-1">{/* transcript */}</MessageScroller>
  </MessageScrollerProvider>
</div>
```

## Composition

```text
MessageScrollerProvider
└── MessageScroller
    ├── MessageScrollerViewport
    │   └── MessageScrollerContent
    │       └── MessageScrollerItem
    └── MessageScrollerButton
```

- `MessageScrollerProvider` is the headless root. It owns opening position, follow-output, anchoring, scroll commands, and visibility state.
- `MessageScroller` is the styled frame.
- `MessageScrollerViewport` receives native scroll input and preserves the visible row when history is prepended.
- `MessageScrollerContent` is the transcript container and defaults to a live log.
- `MessageScrollerItem` wraps each direct row so it can be measured, anchored, preserved, tracked, and addressed by `messageId`.
- `MessageScrollerButton` is an inert scroll control until content exists in its direction.

## Core Concepts

### Anchoring Turns

Mark the row that starts a meaningful exchange with `scrollAnchor`. It can be a user prompt, a system marker, or a group-chat event; it is not tied to a role. A newly appended anchor settles near the top of the viewport and leaves room for its response below.

<ComponentPreview name="message-scroller-anchoring" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Group Chat

Group-chat turn boundaries are often markers rather than a participant message. Put the marker inside its own item and set `scrollAnchor` on that item.

```tsx
<MessageScrollerItem messageId="marcus-joined" scrollAnchor>
  <p>Marcus joined the chat</p>
</MessageScrollerItem>
```

<ComponentPreview name="message-scroller-group-chat" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Keeping Context Visible

`scrollPreviousItemPeek` keeps a slice of the prior item above a newly anchored row. This makes a new turn feel connected to the conversation that led into it.

<ComponentPreview name="message-scroller-previous-context" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Following the Live Edge

With `autoScroll`, streamed output remains visible only while the reader is already at the live edge. Scrolling with a wheel, touch, keyboard, scrollbar, or a direct message jump releases the view. `MessageScrollerButton` returns to the latest reply and re-engages follow-output.

<ComponentPreview name="message-scroller-streaming" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Opening Saved Threads

Use `defaultScrollPosition="last-anchor"` to reopen at the last meaningful turn. It falls back to the end when no anchor exists or the final anchored turn already fits in view. Use `"start"` or `"end"` when those positions better match the product.

<ComponentPreview name="message-scroller-opening-position" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Loading Earlier Messages

`preserveScrollOnPrepend` is enabled by default on the viewport. Give rows stable `messageId` values so the component can preserve a specific visible row when older messages are loaded above it.

<ComponentPreview name="message-scroller-load-history" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Animating New Messages

Animate a `MessageScrollerItem` with transform and opacity. Avoid height, margin, and padding animation because layout changes can fight the scroller's position work. Respect reduced-motion preferences while preserving the same scroll behavior.

<ComponentPreview name="message-scroller-animation" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Jumping to Messages

`useMessageScroller` exposes commands from anywhere inside the provider, including controls outside the styled frame.

```tsx
const { scrollToEnd, scrollToMessage, scrollToStart } = useMessageScroller();

scrollToMessage("message-id", { align: "start", behavior: "smooth" });
```

`scrollToMessage` uses the row `messageId`. It returns `false` when a target is not mounted and cannot be queued; a `true` result means the scroll ran or was queued.

<ComponentPreview name="message-scroller-commands" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Tracking the Reader's Position

`useMessageScrollerVisibility` reports the current anchored turn and the message ids currently visible in document order. Tracking is pay-for-what-you-use: it only runs while a consumer subscribes, and rows need `messageId` values to participate.

<ComponentPreview name="message-scroller-visibility" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

### Reading Scroll State

`useMessageScrollerScrollable` reports whether the viewport can still scroll toward the start or end. The opposite tells you that the corresponding edge has been reached. For styles, prefer the root `data-scrollable` state.

<ComponentPreview name="message-scroller-scrollable" previewClass="h-auto bg-surface p-4 dark:bg-background sm:p-10" />

## Performance

The scroll hot path is imperative: transcript rows do not rerender for each scroll event. The root and viewport mirror relevant state through data attributes, and each item uses `content-visibility: auto` with an intrinsic size so far-off rows can avoid paint work while remaining present for selection, find-in-page, server rendering, and assistive technology.

For the expected range of hundreds to low thousands of rich transcript rows, real DOM items preserve the best selection and accessibility behavior. When a much larger transcript needs virtualization, use `MessageScrollerViewport` as the virtualizer's scroll element and let the virtualizer own the rows.

## Accessibility

`MessageScrollerContent` defaults to `role="log"` and `aria-relevant="additions"`. Set `aria-busy` while a response is streaming so assistive technology receives a coherent update. The viewport is a labelled, keyboard-focusable region; scroll keys signal reader intent, and the inactive scroll button is removed from tab order.

```tsx
<MessageScrollerContent aria-busy={status() === "streaming"}>
  {/* messages */}
</MessageScrollerContent>
```

## API Reference

This is native Solid composition rather than a wrapped primitive. The complete public API is documented in the [Message Scroller source](https://github.com/carere/zaidan/blob/1ced2c35ac60b083865063626e7070b73051df6c/src/registry/kobalte/ui/message-scroller.tsx).

| Part | Purpose |
| --- | --- |
| `MessageScrollerProvider` | `autoScroll`, default opening position, anchors, scroll margins, and visibility state. |
| `MessageScrollerViewport` | Scroll container; `preserveScrollOnPrepend` defaults to `true`. |
| `MessageScrollerContent` | Transcript log with configurable role, live-region, and spacer class. |
| `MessageScrollerItem` | Addressable row with `messageId` and `scrollAnchor`. |
| `MessageScrollerButton` | Start or end scroll control with a configurable behavior and direction. |
| `useMessageScroller` | `scrollToStart`, `scrollToEnd`, and `scrollToMessage`. |
| `useMessageScrollerScrollable` | Start/end scrollability state. |
| `useMessageScrollerVisibility` | Current anchor id and visible message ids. |
