# Solid 2 replacement primitives: capability and parity investigation

Research resolution for [Determine replacement primitive capabilities and behavior gaps for Solid 2](https://github.com/carere/zaidan/issues/496), investigated 2026-09-09. This is a source/API investigation, not a browser parity certification or an implementation spec. Necessary documented public API changes are allowed; website appearance and behavior remain requirements. No old primitive should be retained merely for API compatibility.

## Findings

### Command: Search is available, but its composition model differs

Kobalte Search wraps Combobox, accepts an `options` collection and item/section renderers, and deliberately bypasses internal filtering (`defaultFilter={() => true}`). Applications filter in `onInputChange`. It supplies Input, Listbox, Item, Section, NoResult and Indicator, and defaults to close-on-selection, focus wrapping, and allowing an empty collection. Its selected value is an option (or options), with `onChange`; Search.NoResult depends on `options.length`. [Published Search source](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/search/index.jsx), [Combobox types](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/combobox-root/DbzRduU8.d.ts).

Zaidan currently exposes cmdk child composition (`CommandGroup`, `CommandItem`, `CommandEmpty`) and cmdk-derived props. This is not a drop-in import replacement. Existing grouping/headings and disabled/checked/selected styles also assume cmdk DOM markers; all eight style files contain `[cmdk-group-heading]`. [Wrapper](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/ui/command.tsx), [representative style](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/styles/style-vega.css).

Decision needed: adopt an explicitly data-driven Command public API, or implement a Zaidan-owned child registration layer that produces Search options. The former is smaller and aligns with the allowed API changes; the latter costs lifecycle/ordering/filtering complexity. Neither alternative needs cmdk. Specify filter matching/ranking, group hiding, empty state, disabled item navigation, action dispatch, and persistent inline list versus dialog popup behavior. Existing appearance does not prove Search's default popup/focus behavior matches a command palette. Preserve Zaidan `data-slot` hooks and deliberately map new selection/highlight markers.

### Toast: imperative primitives exist; presentation and convenience API remain Zaidan work

Kobalte exports `toaster.show`, `update`, `promise`, `dismiss`, and `clear`. IDs are numbers; calls take component renderers, not Sonner message/options objects. Promise renderers receive state/data/error. Toast.Region provides duration, limit, swipe direction/threshold, pause on interaction/page idle, and hotkey-related behavior; Toast supplies title, description, close button, progress and root pieces. [Published types](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/index/CRH64cr3.d.ts), [implementation](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/toast/BZZ7jdbA.jsx).

Zaidan's Toaster currently wraps Sonner with top-center positioning, theme, semantic icons, and token colors. Many examples and the site's clipboard button import `toast` directly from `solid-sonner`; changing only Toaster leaves these callers broken. [Toaster](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/ui/toast.tsx), [promise demo](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/examples/docs/toast-promise.tsx), [site clipboard caller](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/components/cli-button.tsx).

Decision needed: expose Kobalte renderer-based calls directly, or provide a small Zaidan `toast` facade for message/description/action, semantic variants and promise states. Either is permitted; use Kobalte for lifecycle in both. Recreate positioning, theme tokens, icons, action/close behavior and stacking animations explicitly. Source support for swipe and timers is not evidence that Sonner's visual stacking and timing are identical.

### Corvu replacements: present, with concrete API seams

- **Drawer:** alpha.2 contains snap points, break points, active/default snap point, swipe velocity/damping, scrollable-child handling and an `openPercentage` context accessor. It builds on Dialog. Corvu `Close`/`Label` become `CloseButton`/`Title`, and polymorphic types change. Existing overlay blur/opacity can continue to derive from open percentage, but Kobalte Overlay has its own opacity behavior that must be reconciled. Test sides, nested/non-modal drawers, controlled snap points, focus restoration, scroll/gesture interaction, and swipe-handle restrictions. [Drawer declarations](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/index/B6JUzNAO.d.ts), [source](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/drawer/DDnMCpAt.jsx), [current wrapper](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/ui/drawer.tsx).
- **OTP:** the single hidden input and slot-context architecture is available. Context still exposes `value`, `activeSlots`, `isInserting`; Root requires `maxLength` and uses `onChange`, not Corvu `onValueChange`. Form disabled/required/readOnly/validation are Root options; pattern belongs to Input. Transfer controlled state to the new Root contract and preserve the existing visual slot/caret layer. Test paste, filtering, completion, deletion, selection, form submission and disabled state. [OTP types](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/otp-field/index.d.ts), [current wrapper](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/ui/input-otp.tsx).
- **Resizable:** Root/Panel/Handle exist; fractions and pixel sizes, controlled sizes, collapse/expand, resize strategy, keyboard handle behavior and `data-orientation` are supported. Replace Corvu types with Kobalte types, preserve the wrapper's visual handle, and validate nested panels, size constraints and keyboard/pointer resize. New internal attributes use `data-kb-resizable-*`; do not preserve internal Corvu selectors by accident. [Types](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/resizable/index.d.ts), [source](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/resizable/index.jsx), [wrapper](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/ui/resizable.tsx).
- **Calendar:** Kobalte has single/multiple/range modes and grid primitives, but replaces Corvu Nav/Table/Cell/CellTrigger composition with its own Grid family and state. Its `DateValue` is native `Date`, explicitly Gregorian-only without per-value time zones. Zaidan owns substantial date-fns/TZDate behavior, matchers, captions, custom days and week numbers; that layer needs a deliberate adapter, especially timezone normalization and range shape. The file named `calendar-hijri.tsx` is actually a standalone PersianCalendar demo using `@internationalized/date` and Button, not the Corvu Calendar wrapper. Preserve it independently; Kobalte's Gregorian limitation is not itself a blocker for that demo. [Kobalte date types](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/types/CfIQoHy3.d.ts), [calendar API](https://unpkg.com/@kobalte/core@2.0.0-alpha.2/dist/index/DdEmxfsg.d.ts), [Zaidan calendar](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/ui/calendar.tsx), [Persian demo](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/examples/docs/calendar-hijri.tsx).

### Drag/drop: usable foundation, substantial application behavior remains

The next.0 API offers draggable/droppable/sortable refs, context with active/over/transform, collision detectors, arrayMove and lifecycle callbacks. `createSortable` combines draggable and droppable; it does not provide dnd-kit's ordering manager or sibling displacement animation. Public types contain no dedicated activation-handle ref, overlay component, modifiers pipeline, activation delay/distance, or public general layout-remeasurement method. These are verified omissions in this artifact's API, not claims that the behavior is impossible to build. [Published public types](https://unpkg.com/@solid-primitives/drag-drop@0.1.0-next.0/dist/types.d.ts), [sortable implementation](https://unpkg.com/@solid-primitives/drag-drop@0.1.0-next.0/dist/sortable.js).

Keyboard pickup/drop use Space/Enter, arrows move by a pixel step (default 25), and Escape cancels; pointer cancellation has a separate callback. Pointer listeners and capture cover pointer-capable touch devices, but caller CSS/gesture arbitration is still required. Drags start immediately on accepted primary pointerdown. Auto-scroll supports the window only, and ignores keyboard drags. Rectangles are cached at start and refreshed on captured scroll; no public refresh API covers arbitrary live layout rearrangement. SSR branches return inert refs/state. These are positive source findings, not browser/device test results. [README](https://unpkg.com/@solid-primitives/drag-drop@0.1.0-next.0/README.md), [draggable source](https://unpkg.com/@solid-primitives/drag-drop@0.1.0-next.0/dist/draggable.js), [context source](https://unpkg.com/@solid-primitives/drag-drop@0.1.0-next.0/dist/context.js).

Zaidan Sortable, Kanban and data-grid row/column DnD currently depend on dnd-kit handles, overlays, sortable indices/groups and event types. Sortable exposes custom move handling and commit snapshots; Kanban supports live cross-column previews, opt-in single commit, restore-on-cancel, column reorder and persistence. These contracts must be recreated above the new primitives. Data-grid exports dnd-kit-derived collision/modifier/event types, so those public types must change. [Sortable](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/blocks/sortable/sortable.tsx), [handles](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/blocks/sortable/item.tsx), [Kanban](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/blocks/kanban/kanban.tsx), [data-grid rows](https://github.com/carere/zaidan/blob/d1ddcf24aa358a43918ae5938eb86506c29e1bba/src/registry/kobalte/blocks/data-grid/data-grid-table-dnd-rows.tsx).

Decision needed: own a shared Zaidan drag interaction layer (handles, overlays, keyboard target navigation, layout changes and nested scrolling), or secure needed upstream additions/pin an approved upstream branch. Keeping dnd-kit is outside the requested direction. Treat handle isolation, interactive descendants, touch scroll versus drag, empty-column targets, nested scroll containers, cancellation rollback and grid keyboard moves as acceptance cases. SSR support may let wrappers simplify existing client-only guards, but remove those only after rendered markup/hydration parity checks.

## Decision frontier and completion boundary

The factual question is answered: all requested primitive families ship, but import substitution alone cannot preserve behavior. No source-level absence forces abandoning the requested replacements. Research does not establish that the current artifacts already meet end-to-end parity.

Sharp next decisions are (1) Command composition/filtering contract, (2) Toast facade/presentation contract, (3) ownership of drag/drop missing behavior and any upstream prerequisites, and (4) Calendar adapter boundaries for existing custom rendering/date semantics. Drawer/OTP/Resizable can be specified as wrapper rewrites with documented type changes and explicit interaction acceptance checks. Actual keyboard, touch, SSR/hydration and visual parity remain implementation acceptance work, rather than claims made by this investigation.
